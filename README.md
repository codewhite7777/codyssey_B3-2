# codyssey B3-2 — AI Git 설명 도우미

Git 변경 사항을 읽어 커밋 메시지와 Pull Request 초안을 만드는 Python 3.10+ CLI 프로젝트입니다. 사용하는 AI는 **Google Gemini**입니다.

## 문서의 역할과 현재 상태

- **README.md:** 설치, API Key 설정, 실행 방법, 출력 예시를 안내하는 과제 필수 문서입니다.
- **[READ.md](READ.md):** 사용자가 요청한 설계 결정, 과제 근거, 단계별 구현·검증 기록입니다.

Git 수집·환경변수 Key 처리·현재 Key 치환·최소 안전 모드와 **Gemini REST 기반 커밋·PR 초안 생성**을 구현했습니다. 2026-10-12 KST 사용자 Mac의 실제 커밋·PR 생성, HTTP 503 오류 처리와 수동 재실행, temperature `1.0`·`0.5` 결과 비교를 확인했습니다. 실제 출력과 검증 범위는 아래 및 [READ.md 11.3절](READ.md#113-실제-gemini-실행과-파라미터-비교-결과)에 기록했습니다.

## 설치와 API Key 설정

Git과 Python 3.10 이상이 필요합니다. 별도 Python 패키지를 설치하지 않습니다.

```bash
git clone https://github.com/codewhite7777/codyssey_B3-2.git
cd codyssey_B3-2
```

이미 클론했다면 기존 프로젝트 루트에서 실행합니다. macOS의 bash/zsh에서는 같은 터미널에서 아래를 **한 줄씩** 실행합니다. `read`가 입력을 기다리면 자신의 Gemini Key를 붙여넣고 Enter를 누른 뒤 나머지 줄을 실행합니다.

```bash
printf 'Gemini API Key를 입력하세요: '
read -r -s AI_API_KEY
printf '\n'
export AI_API_KEY
```

프로그램은 환경변수 `AI_API_KEY`만 읽습니다. `.env`를 자동으로 읽지 않으며, 새 터미널에서는 다시 설정합니다. 실제 Key는 Git에 저장하거나 화면에 출력하지 않습니다. 다른 터미널의 설정과 선택 근거는 [READ.md 3절](READ.md#3-api-key-준비와-설정)에 있습니다.

## 현재 실행 방법

macOS 예시입니다. Python 명령 이름이 `python`인 환경에서는 `python3`를 `python`으로 바꿉니다.

```bash
python3 main.py commit
python3 main.py pr
```

이 두 명령만으로 기본 설정을 사용해 실행할 수 있습니다. 아래 옵션들은 필요할 때만 붙입니다. 과제는 파라미터를 변경할 수 있는 옵션과 기본값을 요구하며, 매번 모든 값을 입력하도록 요구하지 않습니다.

- 프로젝트 루트에서 `git status`와 staged·unstaged의 `git diff`를 읽습니다.
- 변경이 없으면 `변경 사항이 없습니다`를 출력하고 종료합니다. 새 파일만 있으면 `git add` 후 재실행하도록 안내합니다.
- 추적 파일 변경이 있는 `commit`·`pr`에서 Key가 없으면 설정 오류를 출력합니다. Key의 존재 확인과 실제 Gemini 인증은 별개입니다.
- `inspect`는 변경 목록만 확인하며 API를 호출하지 않습니다. 커밋 메시지는 `commit`, PR 제목·본문은 `pr` 명령으로 생성합니다.
- staged와 unstaged를 함께 요약합니다. 실제 커밋에는 staged 내용만 들어가므로 초안을 적용할 때 대상 변경을 확인합니다.

### `--safe-mode`의 의미

안전 모드로 실행할 때는 옵션 하나만 추가합니다.

```bash
python3 main.py commit --safe-mode
```

`--safe-mode`는 값 없이 붙이는 옵션이며, 생략하면 파일·줄 제한을 적용하지 않습니다. 지정하면 **Gemini 요청 전에 diff가 있는 추적 파일을 최대 10개, 모든 파일의 staged/unstaged diff 합계를 최대 200줄**로 제한합니다. diff 헤더·문맥·추가·삭제 줄을 모두 셉니다. 일부 변경을 제외하면 터미널에 경고하고 프롬프트에도 일부 diff임을 표시합니다.

과제 7번이 허용하는 **일부 diff 전송(B)**을 선택한 것입니다. 원본 파일과 Git 인덱스는 수정하지 않으며, Gemini 모델의 안전 설정을 바꾸는 옵션도 아닙니다. `commit`·`pr`의 입력 처리에서 옵션을 생략해도 현재 `AI_API_KEY`와 정확히 같은 문자열은 가립니다. 두 명령의 변경 이유와 생성된 출력에도 같은 치환을 적용합니다.

전송 범위를 줄이는 기능이며 모든 민감정보를 탐지하지는 않습니다. 실행 전 `git diff`와 `git diff --cached`를 검토해 다른 키나 개인정보가 포함되었는지 확인합니다. 제한된 경우 초안은 선택된 변경만 설명하므로 전체 변경을 대표한다고 가정하지 않습니다.

### 생성 옵션

| 옵션 | 기본값 | 처리 |
| --- | --- | --- |
| `--model` | `gemini-3.1-flash-lite` | 요청 URL의 Gemini 모델 이름 |
| `--temperature` | `1.0` | 0~2 범위, 표현의 변동성을 조절하는 생성 옵션 |
| `--max-tokens` | `4096` | 양의 정수, Gemini의 `maxOutputTokens`에 전달하는 생성 토큰 상한 |
| `--context` | 빈 문자열 | 변경 이유·요구사항을 프롬프트에 추가 |

두 생성 명령에서 같은 옵션을 사용합니다. **생략하면 위 기본값이 적용되므로 변경할 값만 입력합니다.** 앞의 세 옵션은 과제 예시의 `-model`, `-temperature`, `-max-tokens` 표기도 받습니다. 파라미터의 의미와 선택 근거는 [READ.md 5절](READ.md#5-cli-옵션과-api-파라미터의-연결)에 있습니다. 예를 들어 안전 모드를 유지하며 temperature만 바꾸려면 다음과 같이 실행합니다.

```bash
python3 main.py pr --safe-mode --temperature 0.5
```

### 출력 예시

다음은 **2026-10-12 KST 사용자 Mac에서 실제 Gemini로 생성한 출력의 발췌**입니다. 입력은 README.md에 `테스트용 변경입니다.` 문장을 추가한 변경이며 두 예시는 기본 temperature `1.0`을 사용했습니다. 전체 조건과 비교 결과는 [READ.md 11.3절](READ.md#113-실제-gemini-실행과-파라미터-비교-결과)에 있습니다.

**커밋:** 별도의 커밋 본문은 생략하고 변경 요약과 제목을 구분합니다.

```text
[DONE] 커밋 메시지 생성 완료
--- Change Summary ---
- README.md 파일에 테스트용 문구 추가

--- Commit Message ---
docs: README.md 테스트용 문구 추가
----------------------
[INFO] AI가 만든 초안입니다. 변경 내용과 제목을 검토한 뒤 적용해 주세요.
```

**PR:** 변경 요약, PR 제목, 세 섹션의 본문을 구분합니다.

```text
[DONE] PR 초안 생성 완료
--- Change Summary ---
- README.md 파일 내 테스트용 문구 추가

--- PR Title ---
README.md에 테스트용 변경 사항 추가

--- PR Body ---
## Why
- README.md 파일의 변경 사항을 확인하기 위한 테스트 용도입니다.

## What
- README.md 파일 하단에 '테스트용 변경입니다.'라는 문구를 추가하였습니다.

## How to Test
- README.md 파일을 열어 추가된 문구가 정상적으로 표시되는지 확인합니다.
----------------------
[INFO] Gemini API 호출 횟수: 1회
```

커밋 제목은 50자 이내를 권장하도록 요청하고 Python에서 한 줄·최대 72자로, PR 제목은 한 줄·최대 80자로 후처리합니다. 제목을 정리했으면 경고를 표시합니다. PR 본문은 `Why`, `What`, `How to Test`와 각 섹션의 불릿을 Python이 구성합니다. 필수 필드 누락·빈 목록·잘못된 JSON 결과는 오류로 종료합니다. 배경 근거가 부족하면 AI가 확인 필요로 표시하도록 요청하며, 제안한 테스트 방법은 실제 통과 기록과 구분해 검토합니다.

API Key 누락, HTTP 인증·권한·할당량 오류, 연결 실패, 시간 초과, 응답 잘림을 원인과 함께 안내합니다. 자동 재시도는 없으며 요청 실패도 시도 횟수 1회로 표시합니다. 요청 횟수는 인증 성공이나 과금 확정을 의미하지 않습니다.

## 검증

```bash
python3 -m unittest discover -v
```

4단계([PR #10](https://github.com/codewhite7777/codyssey_B3-2/pull/10))에서 2026-10-12 KST, Python 3.12.14로 **총 53개 테스트를 통과**했습니다. 실제 임시 Git 저장소와 가짜 Key를 사용하고 CLI의 HTTP 요청을 모의 처리했습니다. 요청 주소·옵션·context·전송 제한·Key 치환, 커밋 72자·PR 80자 제목, PR의 필수 세 섹션·불릿, 오류·요청 횟수를 확인했습니다. 상세 기록은 [READ.md 7.2절](READ.md)에 있습니다.

5단계에서는 프로그램·테스트 코드를 수정하지 않고, 임시 저장소에서 별도 Python 프로세스로 **CLI 실행 4건**을 확인했습니다. `commit`·`pr` 각각 변경 없음은 종료 코드 0, 추적 파일 변경과 Key 누락은 종료 코드 1이었으며, 모두 호출 횟수 0회와 원본 파일·Git 인덱스 보존을 확인했습니다. HTTP 모의 처리는 사용하지 않았고 실제 API도 호출하지 않았습니다. 이 4건은 기존 자동 테스트 53개와 별도의 확인 기록입니다.

### 실제 API 실행·파라미터 비교 결과

2026-10-12 KST 사용자가 Mac에서 실행한 로그로 실제 커밋·PR 생성과 파라미터 비교를 확인했습니다. 모델은 `gemini-3.1-flash-lite`, 토큰 상한은 `4096`, `--safe-mode`를 사용했고 매 실행 README.md 1개 파일·diff 10줄이 수집되었습니다.

| 실행 | 결과 | 공유 로그의 API 호출 횟수 |
| --- | --- | --- |
| `commit --safe-mode` | 생성 성공, 제목 26자 | 해당 줄은 공유 로그에 없음 |
| `pr --safe-mode` 최초 실행 | HTTP 503과 제공자의 과부하 안내 | 1회 |
| `pr --safe-mode` 수동 재실행 | 생성 성공, 제목 24자 | 1회 |
| `pr --safe-mode --temperature 0.5` | 생성 성공, 제목 20자 | 1회 |

성공 3건·실패 1건의 실행 기록입니다. 커밋 성공 로그에 없는 호출 횟수 줄은 보완해서 쓰지 않았으며, PR의 세 실행에서는 각각 1회 표시를 확인했습니다. 실제 Key와 실행 환경의 비밀값은 기록하지 않습니다.

| PR 비교 | temperature 1.0 | temperature 0.5 |
| --- | --- | --- |
| 제목 길이 | 24자 | 20자 |
| 본문 길이 | 167자 | 133자 |
| 섹션·불릿 | 필수 세 섹션, 각각 1개 | 필수 세 섹션, 각각 1개 |
| 변경 배경 | 테스트 목적 설명 | `변경 배경 확인 필요` |

본문 길이는 헤더·공백·내부 개행을 포함하고 마지막 개행을 제외한 문자 수입니다. 같은 README 변경을 유지하며 temperature만 바꿔 실행한 결과로, 이번에는 본문 길이와 표현·배경 설명에 차이가 있었습니다. 한 번의 비교로 같은 차이의 반복 재현이나 temperature만의 효과를 입증하지는 않습니다. 실제 출력, 조건의 확인 범위, 초안 보완 예시는 [READ.md 11.3절](READ.md#113-실제-gemini-실행과-파라미터-비교-결과)에 있습니다.

비교에 사용한 명령은 다음과 같습니다. 직접 확인할 때는 같은 diff·모델·안전 모드·context를 유지하고 각 실행의 성공을 확인한 뒤 다음으로 진행합니다.

```bash
python3 main.py commit --safe-mode
python3 main.py pr --safe-mode
python3 main.py pr --safe-mode --temperature 0.5
```

## 과제 진행 상태

**필수 기능 구현, 기존 자동 테스트, 실제 커밋·PR 생성과 파라미터 비교 기록을 완료했습니다.** 사용자 실제 실행과 개발 환경의 모의 테스트를 구분해 기록했습니다. 이번 문서 갱신에서는 프로그램·테스트 코드를 수정하거나 자동 테스트를 다시 실행하지 않았습니다.

평가 항목 2~4의 설계·파라미터·검토 이유는 [READ.md 11.2절](READ.md#112-평가-항목-24-현재-구현을-설명하는-근거)에 정리되어 있습니다. 다음 학습은 해당 코드와 실제 출력의 차이를 본인의 말로 설명하는 것입니다.

과제 7번의 **일부 diff 전송(B)**을 선택했습니다. 일반 비밀값 탐지, 별도 파일 제외 정책, 상한 조절 옵션, dry-run, 팀 컨벤션 등 추가 기능은 이번 범위에서 제외합니다. [범위 검토와 과제 근거](READ.md#0-과제-필수사항에-맞춘-구현-범위)를 확인할 수 있습니다.

각 단계의 목적을 먼저 READ.md에 기록한 뒤 구현 → 검증 → 커밋·PR 머지 순서로 진행하며 다음 단계 코드는 미리 작성하지 않습니다. 이 저장소의 개발 과정에서 하는 GitHub 반영과 별개로, **프로그램 자체는 커밋·push·PR 생성·머지를 실행하지 않습니다.** 생성된 텍스트는 사용자가 검토하고 적용합니다.
